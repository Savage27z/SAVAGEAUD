# Target census — 2026-09-22 (bug-hunting resume: gambling + new protocols)

## Method + honest limits
- DefiLlama `/protocols` for new/small EVM protocols (fields include `tvl`, `listedAt`, `category`,
  `chains`, `address`, `audits`, `audit_links`, `url`, `twitter`).
- **`audits` is a STRING ('0'..'3'), not a list or int.** A truthy test labels every protocol
  "audited" — caught by control against Binance CEX (`'0'`) / Lido (`'2'`). Parse with int().
- **`address` is `chain:0x…`-prefixed and the prefix is LOWERCASE** (`base:0x…`), which breaks a
  title-case chain map. Most protocols carry no address at all.
- **DefiLlama has no Casino/Gambling bucket** (confirmed: only `Yield Lottery` 1, `Prediction Market`
  2, `Gaming` 1 in the size band) and does not index consumer casinos (death.fun/nar.bet class).
- **Dapp directories are walled for scraping**: DappRadar returns a ~28KB challenge page (0 dapp
  slugs) and the Alchemy dapp lists time out under headless Chrome. Not defeated by design.
- **"Best provably fair casino" web results are affiliate listicles** (cryptoslate/cryptocasinos/
  readwrite/coingabble) listing custodial web2 casinos — no contracts, wrong class for a contract audit.
- **Verification checks came back UNCONFIRMED, not "unverified"**: Blockscout returned
  `verified=None` for EntryPoint v0.6 (`0x5ff137d4…`) and v0.7 (`0x0000000071727de2…`), which are
  certainly verified. The check failed its own positive control → rate-limited/broken, so no
  verification verdict from this pass may be used.

## CORRECTION — 2026-09-28 (after TayDex closed, picking the next target)

### The `age_d` field was misread, and it inflated the shortlist

`age_d == 0.0` does **not** mean "brand new". It means DefiLlama has **no listing date**, and the
entries it covers are dominated by **2020–2021 legacy protocols** — CREAM, Yam Finance, Geist,
InsurAce, Indexed Finance, Alchemix V2, PEAKDEFI, Penguin Finance, Olive Cash, PolyQuity, FilDA.
Treating them as "listed recently" is what made the list look like 181 candidates. It is really:

- 181 unaudited non-DEX
- of which **148 have `age_d == 0.0`** (no listing date → mostly legacy)
- of which **33 have a real age**, and **97 of the 181 carry `audit_links`** despite `audits = 0`
  (the string-vs-int flaw already documented above)

**Clean shortlist: 27 targets** = genuinely new (`age_d >= 3`) + no audit links + non-DEX.
Top of it by TVL: Enhanced ($156K Eth), GILDer ($118K Base), zERC20 ($97K), Murk Finance ($65K Monad).

### Working pre-vet oracle found (replaces the broken one)

Two oracles were tried and one works:

| oracle | verdict |
|---|---|
| `base.blockscout.com/api/v2/smart-contracts/{addr}` | **BROKEN** — returns `is_verified=None` even for a known-verified control (USDC on Base). Unusable. |
| DefiLlama `address` field | **WRONG FIELD** — it is the protocol's *governance token* (LDO, AAVE), not its contracts. |
| **Sourcify `sourcify.dev/server/v2/contract/{chainId}/{addr}?fields=all`** | **WORKS** — gives `match`, full `sources` (file list + content), `abi`, `metadata`, `storageLayout`. |

**Sourcify `?fields=all` is the audit-ability oracle.** It answers the question that decides whether
a target is worth a slot — *is there source to read?* — and it hands you the source, the ABI and the
**storage layout** in one call. Use it before committing to any target.

### Harvester pitfalls (both hit, both fixed)

1. JS-only SPAs yield 0 addresses from the HTML alone — follow `/_next/static/…` and `/assets/…`
   chunk paths, not just `<script src>`.
2. **Exclude chain predeploys before reporting verification.** OP-stack `0x4200…00xx` and
   `0x0000…00xx` system contracts matched on Sourcify and were reported as the project's
   "VERIFIED" contracts. They belong to the chain, not the project. Whitelisting infra
   (Uniswap routers, multicall3, Permit2, EntryPoints, WETH/USDC/DAI/WBTC) matters too.
